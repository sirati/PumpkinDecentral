# Decentral Player-Action Mesh — Full Detail Plan

## Summary
- Add opt-in cluster mode: disk-only primary plus N QUIC-meshed secondaries. Player actions only; mobs, TNT, block ticks stay local.
- Each secondary authoritatively simulates its local players with low ping, replicates optimistically, converges via deterministic ordering and per-chunk acceptance.
- Wire uses many small single-purpose structs sent as homogeneous arrays, `postcard`+`serde`, `quinn` uni streams plus unreliable datagrams, NTP-disciplined wrapping `u16` tick stamps.
- Hot path is lock-free new code: thread-local double banks, `Box` handoff over `mpsc`, fuse task off tick thread, `oneshot` for queries. Existing MC-client send paths unchanged.
- TLS: each server self-generates cert locally, operator distributes public certs out of band, peers pin hashes. Strict unanimous join and drain leave.

## Code Investigation Findings
- Tick uses `rayon` `par_iter` over worlds and players inside `Server::tick`, entered on a shared `tokio` runtime handle; `Player::tick` also runs there. Banks must therefore be per-Rayon-worker thread-local.
- `Player` carries many `std::sync::Mutex` fields and `ArcSwap`; `Level` uses `DashMap` for loaded chunks plus `Mutex` for chunk loading and thread tracker. New cluster hot path avoids locks; existing locks are not removed in v1.
- Client actions arrive in `net/java/play` handlers (`player_action`, `attack`, `use_item_on`, `interact`) and call `World::break_block` / `Player::attack` outside tick. Every such handler needs a narrow emit hook into thread-local banks.
- Block writes flow through `World::set_block_state` / `break_block` with events, drops, POI, lighting, neighbors. Replication wraps at that boundary and captures `expected_old_state` plus undo.
- Inventory place path spans block placer plus `pumpkin-inventory` screen handlers and held-item state; atomicity is implemented as one `PlaceBlock` message carrying stack delta plus undo counts.
- `quinn` is not yet a dependency; only `quinn-udp` appears transitively. `rustls` exists in workspace. No existing cluster cert logic.

## Key Changes
- **Crate and frozen types:** new `pumpkin-cluster` with `GlobalPlayerId`, `TickStamp`, `Seq`, `ChunkAddr`, `EntityRef`, per-type update structs, batch headers, hash-order function, time helper signatures.
- **Small-struct arrays:** each tick batch is a set of homogeneous arrays: `ArmorUpdate`, `HandUpdate`, `SneakUpdate`, `SprintUpdate`, `BlockingUpdate`, `SwingUpdate`, `SkinLayersUpdate`, `EatStart`, `EatAbort`, `BreakAnim`, `BreakBlock`, `PlaceBlock`, `HitPlayer`, `HitEntity`, `FireBowCrossbow`, plus datagram `PosUpdate`. Type tag appears once per array.
- **QUIC and certs:** `quinn` endpoints, high uni-stream limit, datagrams on; per-server local keypair generation plus export command; config stores own paths and peer `{server_id, addr, pinned_pubkey_hash}`; handshake fails closed on mismatch; rotation is manual re-distribution.
- **Streams:** 4 long-lived uni streams per player by category; 4 shared uni streams for owned entities; `CTRL` for directory and membership; `CHUNK_REQ` and `CHUNK_DATA`; `ACCEPT` for batched per-tick resolutions with `new_holders` lists.
- **Time:** NTP client against online servers, cached offset, `now_tick` mapping to 50ms units as wrapping `u16`; pause new logins when offset unknown or above threshold.
- **Banks and fuse:** per-worker `BankA/B` with one `Vec` per update type; push is synchronous and lock-free; tick end moves full `Box<Bank>` over `mpsc` and takes an empty one back from cap-1 return channel; dedicated async fuse task concatenates, stamps, routes by holder map; slow fuse logs at most once per minute; MC-client packets keep current behavior.
- **Buckets and acceptance:** `tick -> per-chunk pending` queues; updates carry 1–3 chunk addresses; only holders receive them; batched accepts per tick; late holders learned from request broadcasts and resolution-attached holder lists delay global acceptance; globally accepted ticks promote together.
- **Ordering and undo:** `xxhash(cluster_seed, tick, gid)` total order with `(server,player)` tie-break; pairwise commutativity for 3+ conflicts; stale block-type check rejects; losers run stored undo only, then apply winner; never rebuild from replay; movement and login remain infallible.
- **Chunks:** have/drop gossip; lowest-id holder fetch; negative reply on dropped; payload is ground-truth snapshot plus known pendings plus holder list; requester replays pendings onto local copy.
- **Dual state:** per-chunk `ground_truth` and `local_truth`; remote and local optimistic updates hit local only; accepted ticks apply to ground at once.
- **Primary:** no players; ingests accepted ticks; runs existing world and playerdata save; secondaries disable disk writes in cluster mode.
- **Membership and entities:** unanimous join before hosting players; leave only when empty or after entity handoff to chunk holders; spawner owns entity ticks; ghosts on remotes filtered by chunk holding.
- **Client reconcile:** remote ghosts through entity tracker; block rollbacks and equipment corrections sent as normal MC packets after conflict loss.
- **Config and ops:** cluster config, CLI flags, example file, setup docs for cert exchange, metrics, throttled slow-path logs, debug status commands.

## Assumptions
- `postcard` is acceptable for zero-copy-style needs; `quinn` with operator-distributed pinned certs; online NTP directly.
- Player join and accepted movement are infallible; all other replicated actions declare fallibility explicitly.
- Unclean partitions require operator re-admit; no auto-merge in v1.
