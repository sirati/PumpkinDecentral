# Cluster acceptance requirements

This is an unsigned acceptance audit. The signed plans and their final verbatim amendments govern. Every live proof below is **untested**. A registered assertion, preparation queue, successful compilation, or focused core test does not prove runtime producer-to-client wiring.

The live fixture has one listener-free primary, two secondaries, and Java clients with forwarded deterministic UUID/profile properties. Every selected invocation and every full-spec mode must finish successfully against fresh processes. Child logs are inspected after exit. Bedrock handler/protocol tests, workspace/Nix builds, and deployment are separate gates.

## Invocation ledger

The authoritative selected-ID list is `src/scenario_catalog.rs::REQUIRED_SCENARIOS`. It currently contains92 IDs. The five additional mandatory modes are `baseline`, `normal-feature-omission`, `full-radius-recovered-latency`, `early-chunk-streaming`, and `large-admin-snapshot`. Every one remains **untested**. The baseline includes arena, item setup, global services, same/cross-secondary reconnect, and primary persistence; individual selected assertions do not replace it.

Run the supervisor's complete matrix only after source preparation and the root's live-server restriction is lifted. Accepted preparation must come from actual source ActionRefs and Ground state. Missing preparation or record hooks fail the invocation; they are never a skip or success. Per-invocation results must retain command, source revision, process exit statuses, exact scenario evidence, client assertions, secondary hashes/generation counters, and bounded diagnostic audit.
